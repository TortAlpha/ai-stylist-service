# SC Frontend — v1 Specification

## Overview

Angular 19+ SPA for a branded second-hand clothing e-commerce platform. The app serves two roles: **admin** (inventory manager) and **user** (buyer). The primary admin user is an older person with limited internet experience — the UI must be extremely simple, intuitive, and forgiving.

## Internationalization (i18n)

- Two languages: **English** (default) and **Russian**
- Language selection saved in a cookie
- Language switcher visible in the header (flag icons or clear labels)
- Only UI text is translated — product content (names, descriptions) is entered in one language by the admin

## UX Principles

- **Target audience**: an older person who is not tech-savvy
- Large, clearly labeled buttons with text (not icon-only)
- Generous spacing, minimum 16px body font
- Obvious visual feedback: loading spinners, success/error toasts
- Confirmation dialogs before destructive actions (delete, status changes)
- No complex multi-step wizards — prefer single-screen forms with clear sections
- Consistent layout and navigation across all pages
- Fully mobile-responsive (both catalog and admin panel)

## Default Pagination

- **12 items per page** across all paginated lists (catalog, admin product list, listings)
- Paginator shows page numbers, first/last, and total count

## Authentication & User Management

### Registration
- Only **user** role can register (role is `'user'` by default in `user_db`)
- Fields: name, surname, email, password, phone (optional)
- Route: `/auth/register`

### Login
- Fields: email, password
- Route: `/auth/login`
- On success: store tokens, redirect to catalog (user) or admin panel (admin)

### Token Management
- JWT access token + refresh token
- Auth interceptor attaches `Authorization: Bearer {token}` to all `/api` requests
- On 401: attempt silent refresh; if refresh fails — logout and redirect to login

### My Profile (`/profile`)
- Auth-guarded (user or admin)
- Editable fields: name, surname, email, phone number
- Edit via modal dialog
- Address management: list, add, edit, delete addresses (each in modal)
- Display user role (read-only)

## Pages & Features

### 1. Catalog (`/catalog`)

**Access**: everyone (unauthorized, user, admin)

Public product listing using the storefront view (only `ready` + `in_stock` products).

**Layout**:
- Left sidebar: filter panel
- Main area: product card grid (responsive: 4 cols desktop, 2 cols tablet, 1 col mobile)
- Top bar: search by name (text input), sort dropdown, result count

**Filters** (left panel):
| Filter | Type | Source |
|---|---|---|
| Brand | Multi-select dropdown | `GET /api/brands` |
| Category | Multi-select dropdown (hierarchical) | `GET /api/categories` |
| Product Type | Multi-select (Clothing, Footwear, Bags, Jewelry, Accessories) | `GET /api/types` or hardcoded from `product_type` |
| Gender | Radio buttons (Male, Female, Unisex) | Enum |
| Condition | Checkboxes (New with tags, Excellent, Good, Fair) | Enum |
| Price Range | Min/Max number inputs | Free input |
| Season | Multi-select | `GET /api/tags/seasons` |

**Sort options**: Price (asc/desc), Date added (newest first), Name (A-Z)

**Product Card** (in grid):
- Preview image (or placeholder if none)
- Product name
- Brand name + tier badge (luxury/premium/mass)
- Final price (with original price struck through if discounted)
- Condition badge
- Size label (if applicable)

**Click on card** → navigates to product detail page (`/products/:id`)

### 2. Product Detail Page (`/products/:id`)

**Access**: everyone

**Layout**:
- Left: image gallery (main image + thumbnails; click to enlarge)
- Right: product info

**Product Info**:
- Name, SKU
- Brand (name, tier, country)
- Category (with parent if exists), gender
- Price block: original price, discount %, final price
- Status badge
- Condition, material, color, year of release
- Flags: vintage, collab (+ collab name), limited edition
- Special notes
- Type-specific details:
  - Clothing: size, fit
  - Footwear: shoe size, size system
  - Bags: dimensions (W x H x D cm), handle type
  - Jewelry: metal, stone, clasp type
  - Accessories: (no extra fields)
- Tags: style tags, vibe tags, seasons

### 3. Admin Panel — Product List (`/admin/products`)

**Access**: admin only

Paginated table of **all** products (any status).

**Table columns**:
| Column | Description |
|---|---|
| Preview | Small thumbnail |
| SKU | Product SKU |
| Name | Product name |
| Brand | Brand name |
| Category | Category name |
| Type | Product type |
| Status | Status badge (color-coded) |
| Price | Final price |
| In Stock | Yes/No indicator |
| Qty | Quantity |
| Actions | Manage, Listings, View History buttons |

**Top bar**:
- Search by name (text input)
- Filter dropdowns: brand, category, type, status, gender, condition, in_stock
- **"Add Product"** button (top-right) → opens Add Product Modal

**Row actions**:
- **Manage** → opens Edit Product Modal
- **Listings** → navigates to `/admin/products/:id/listings` (Product Listings page)
- **View History** → navigates to `/admin/products/:id/history` (Product History page)

### 4. Add Product Modal

**Access**: admin only (opened from Admin Panel)

Modal dialog with sections:

**Basic Info**:
- Name (required, text)
- Brand (required, select dropdown — fetched from `GET /api/brands`)
- Category (required, select dropdown — fetched from `GET /api/categories`)
- Product Type (required, select — Clothing/Footwear/Bags/Jewelry/Accessories)
- Status (required, select — fetched from `GET /api/statuses`)
- Original Price (required, number)
- Discount % (optional, number 0-100)
- Currency (optional, default EUR)
- Quantity (optional, default 1)
- Product URL (optional, text — external link)

**Details**:
- Condition (required, select: New with tags / Excellent / Good / Fair)
- Material (optional, text)
- Color (optional, text)
- Year of release (optional, number)
- Is Vintage (checkbox)
- Is Collab (checkbox) → shows Collab Name field when checked
- Is Limited Edition (checkbox)
- Special Notes (optional, textarea)

**Type-Specific Details** (shown dynamically based on Product Type selection):
- Clothing: Size (text), Fit (select: Regular/Slim/Oversized/Relaxed)
- Footwear: Shoe Size (text), Size System (select: EU/US/UK)
- Bags: Width cm, Height cm, Depth cm (numbers), Handle Type (select: Shoulder/Crossbody/Hand/Backpack/Tote)
- Jewelry: Metal (text), Stone (text), Clasp Type (text)
- Accessories: no extra fields

**Tags**:
- Style Tags (multi-select, from `GET /api/tags/styles`)
- Vibe Tags (multi-select, from `GET /api/tags/vibes`)
- Seasons (multi-select, from `GET /api/tags/seasons`)

**Actions**: Save (POST `/api/products`), Cancel

### 5. Edit Product Modal (Manage)

**Access**: admin only (opened from Admin Panel row)

Same layout as Add Product Modal but pre-filled with current product data.

**Additional sections**:
- **Images management** (max 10 images per product):
  - View current images (thumbnails grid)
  - Upload new images (multipart, `POST /api/products/:id/images`)
  - Upload/change preview image — separate from regular images (`POST /api/products/:id/preview`)
  - If no preview is uploaded, the first regular image is used as preview
  - Delete images
  - Reorder images via drag-and-drop (Angular CDK DragDrop)
- **Tag management**:
  - Current style/vibe/season tags shown as chips
  - Add/remove via multi-select
  - Uses `PUT /api/products/:id/tags/styles`, `/vibes`, `/seasons`

**Saving**: PATCH `/api/products/:id` with `expected_version` (optimistic locking). On `StaleVersion` error — show message "Product was updated by someone else, please refresh."

### 6. Product History Page (`/admin/products/:id/history`)

**Access**: admin only

Displays the audit log for a specific product.

**Layout**: table or timeline view

**Columns/Fields**:
- Version number
- Changed at (timestamp)
- Changed by (user ID or name if resolvable)
- Changed fields: show diff — highlight what changed between versions (name, price, status, etc.)

**Back button** → returns to Admin Panel

### 7. My Listings (`/admin/listings`)

**Access**: admin only

Paginated table of **all** listings across all products.

**Table columns**:
| Column | Description |
|---|---|
| Product | Product name (or SKU) |
| Marketplace | Marketplace name (Telegram, eBay, Etsy, KP) |
| Status | Listing status badge (active/paused/sold/removed) |
| Listing Price | Price on marketplace |
| Sold Price | If sold |
| External URL | Link to marketplace listing |
| Listed At | Date |
| Actions | Show Product Listings button |

**Row action**:
- **Show Product Listings** → navigates to `/admin/products/:productId/listings`

### 8. Product Listings Page (`/admin/products/:id/listings`)

**Access**: admin only (reached from Admin Panel row "Listings" button or from My Listings "Show Product Listings")

Manages listings for a **single product**.

**Header**: Product name + SKU

**Listing table** (same columns as My Listings, minus Product column)

**Actions**:
- **Add Listing** button → opens Add Listing Modal
- Per-row: **Edit** (modal), **Delete** (with confirmation)

**Add/Edit Listing Modal**:
- Marketplace (required, select — fetched from `GET /api/listings/marketplaces` or similar)
- External ID (optional, text)
- External URL (optional, text)
- Listing Price (optional, number)
- Currency (optional, text)
- Status (select: active/paused/sold/removed) — for edit only
- Sold Price (optional, number) — shown when status = sold

All sub-actions use modal dialogs (PrimeNG Dialog or similar):
- Add/Edit Product

- Have clear Save/Cancel buttons

## Tech Stack

- **Framework**: Angular 19+ (standalone components, new control flow)
- **UI Library**: PrimeNG
- **State**: NgRx Signal Store
- **Forms**: Reactive Forms

- **Styling**: SCSS
- **Icons**: PrimeIcons
- **Change Detection**: OnPush on all components
- **Signals**: Prefer signals over BehaviorSubject for local state

## Resolved Decisions

1. **Admin creation**: Seed in DB (already done: admin@sc.com / admin1234). No admin registration in UI.
2. **Forgot password**: Not in v1 — deferred to v2.
3. **Max images per product**: 10.
4. **Preview image**: Separate upload from regular images. If no preview uploaded, the first regular image is used as preview automatically.
5. **Image management**: Full operations — upload, delete, drag-and-drop reorder. Preview is a separate upload.
6. **Product status transitions**: No restrictions — admin can set any status. History tracks all changes.
7. **Notifications**: Not in v1 — deferred to v2.
8. **Password change**: Not in v1 — deferred to v2.
9. **Mobile responsiveness**: Fully responsive — both catalog and admin panel must work on mobile.
10. **Product content language**: Single language content, only UI is bilingual (EN/RU).
